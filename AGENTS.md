## Product

**QUT Classmate** is a student timetable planner for Queensland University of Technology (QUT). It replaces the painful parts of Allocate+ / QUT Virtual for:

1. **Unit search** — look up a unit code, see all class times
2. **Timetable builder** — pick classes, detect conflicts, weekly view
3. **Auto-generator** (nice-to-have) — Monte Carlo schedule optimizer
5. **Export** — `.ics` / Google Calendar

**Target users:** QUT students planning semesters.  
**Production URL (historical):** `https://qut-classmate.vercel.app/`  
**Brand colour:** `#003A6E` (QUT blue)

### ✅ Use: QUT Virtual 4 SolrQuest (guest session, no student login)

Base: `https://qutvirtual4.qut.edu.au`

Legacy endpoints are **dead or authenticated** — do not rely on:

| Endpoint | Status |
|----------|--------|
| `qutvirtual3.qut.edu.au` HTML scrape | Unreliable / deprecated |
| `mytimetable.qut.edu.au/aplus/rest/timetable/subjects` | Requires auth |

### Timetable classes — `getUnitClasses`

```
GET /web/qut/search
  ?p_p_id=SolrQuest_WAR_solrquest
  &p_p_lifecycle=2
  &p_p_state=normal
  &p_p_mode=view
  &p_p_resource_id=getUnitClasses
  &p_p_cacheability=cacheLevelPage
  &_SolrQuest_WAR_solrquest_timePeriodId={periodId}
  &_SolrQuest_WAR_solrquest_unitCode={UNIT}
  &_SolrQuest_WAR_solrquest_versionNumber={version}
```

**Required headers:** `X-CSRF-Token`, `X-Requested-With: XMLHttpRequest`, session cookies, `Referer` to unit search page.

**Two-step flow (mandatory):**

1. **Bootstrap guest session** — GET the unit search page:
   ```
   /web/qut/search?profile=UNIT&params.showOldUnits=false&params.query={UNIT}
   ```
   Extract from HTML:
   - `Liferay.authToken = '...'` → CSRF token
   - `Set-Cookie` headers → cookie jar

2. **Parse `versionNumber` per teaching period** from embedded `getUnitClasses` URLs in that HTML. **Do not hardcode `versionNumber=1`.** Example: `EFB335` uses `1`, `CAB201` uses `3`.

3. **Call `getUnitClasses`** with cookies + CSRF + correct `versionNumber`.

**Response shape (JSON):**

```json
{
  "data": [{
    "ACTIVITY_GROUP_CD": "LEC01",
    "DESCRIPTION": "Lecture - (Week 1-13) (Internal Mode)",
    "CLASS_START_DAY": "THU",
    "CLASS_TIME_DISPLAY": "9:00 AM - 11:00 AM",
    "CLASS_NO": "01",
    "STAFF": "<a ...>Name</a>",
    "LOCATION": "GP Z401" | "Online" | HTML link
  }]
}
```

**Error cases:**

| Situation | Signal |
|-----------|--------|
| Discontinued unit (e.g. CAB202) | Search page has "No results", no `getUnitClasses` URLs |
| Unit exists, wrong semester | Unit found but no URL for that `timePeriodId` |
| Missing CSRF / cookies | `{"errorMessage":"You have not provided a valid session token"}` |

### Unit catalog — search HTML (not JSON)

**Current units** — paginated prefix search:

```
/web/qut/search?profile=UNIT&params.query={PREFIX}&params.showOldUnits=false&params.start={0,10,20...}
```

- Parse only `.search-unit-info h4.content-title` (ignore course results like `IX85 - Bachelor of...`).
- Modern format: `CAB201 - Programming Principles` → code `CAB201`
- **Use 3-letter prefixes** (`CAB`, `EFB`, …) — 1–2 letter searches miss units. Paginate when a page returns 10 results.
- ~17k prefixes (AAA–ZZZ); run as offline script with concurrency (~4–6), dedupe by code.

**Legacy/historical units** — wildcard (optional):

```
/web/qut/search?params.query=*&profile=UNIT&params.showOldUnits=true&params.sortKey=0&params.start={n}
```

Returns old formats like `CH 815-2 - Inorganic Chemistry II`. Paginate until empty page.

**Output:** commit `data/qut-unit-codes.json` with `{ codes, units: [{ code, title, legacy }], scrapedAt, stats }`.

## Teaching periods (auto-discovered)

Do not hand-maintain a period list. QUT rotates these IDs every year and silently
delists the old ones, which is why the app used to return "No timetable found" for
periods that looked valid.

`data/teaching-periods.json` is generated by `scripts/discover-periods.js`, which
scrapes the `p_time_period_id` / `p_teaching_period` pairs QUT publishes in every
unit search page. `lib/teaching-periods.ts` reads that file and derives everything
from it: the dropdown, the default period, and `shouldUseVirtual4API`.

```bash
npm run periods:refresh     # re-discover and rewrite data/teaching-periods.json
node scripts/discover-periods.js --dry-run   # print without writing
```

`.github/workflows/refresh-periods.yml` runs the same thing monthly and opens a PR
when the IDs move. As of Oct 2026 it discovered:

| ID | Period |
|----|--------|
| `4382869` | Semester 2, 2027 |
| `4382863` | Semester 1, 2027 |
| `4381474` | Semester 2, 2026 |

Exchange periods (`XCH-*`) exist upstream and are deliberately excluded — they
duplicate the same semester with an exchange-specific class list, so selecting one
instead of the plain semester silently hides most classes. `discover-periods.js`
drops them, and `lib/teaching-periods.ts` filters defensively so a stale JSON file
cannot reintroduce them.

Single-school variants (`4382870`, `4381475`) appear on only one unit page; they are
kept in the valid-ID set but filtered out of the picker by `seenOnUnits`.

Build failure mode to watch for: QUT changes its markup, the regex in
`discover-periods.js` stops matching, and the script exits non-zero. That is
deliberate — the CI job fails loudly rather than quietly emptying the list.

## Recommended minimal architecture (greenfield)

```
app/
  page.tsx                    # 4 tabs: Timetable | Campus Explorer | Course Planner | Unit Search
  api/timetable/search/route.ts   # proxy to QUT Virtual 4
  api/units/route.ts          # optional: serve cached catalog
lib/
  qut/
    session.ts                # guest bootstrap (CSRF + cookies)
    timetable.ts              # getUnitClasses + normalize → TimetableEntry
    units.ts                  # parse search HTML + scrape helpers
  types.ts                    # TimetableEntry, SelectedClass, TeachingPeriod
data/
  qut-unit-codes.json         # scraped catalog (committed)
scripts/
  scrape-units.ts             # offline catalog refresh
```

**Stack suggestion:** Next.js App Router, React, Tailwind, shadcn/ui. Skip AWS CDK, duplicate rate-limit contexts, stub files, and 4000-line static unit arrays.

### Normalized `TimetableEntry`

```typescript
interface TimetableEntry {
  class: string           // display label incl. weeks/mode
  activityType: string    // "Lecture", "Tutorial", …
  classTitle: string
  dayFormatted: string    // "Monday"
  startTime: string       // "9:00am"
  endTime: string
  location: string
  locationBuilding: string
  locationRoom: string
  teachingStaff: string
  unitCode?: string
  teachingPeriodId?: string
}
```

Activity type prefix map: `LEC→Lecture`, `TUT→Tutorial`, `PRA/PRC→Practical`, `WOR→Workshop`, `STU→Studio`.

## Caching & rate limits

| Layer | Purpose | Notes |
|-------|---------|-------|
| Client `localStorage` | Timetable results, selected classes | 30-day TTL; key `timetable-{UNIT}-{periodId}` |
| Server KV/Redis | Timetable API cache | Optional; 1h TTL; graceful fallback if unset |
| Middleware | Daily cap for `/api/timetable/search` | **Off by default.** Set `RATE_LIMIT_ENABLED=true` to restore 15 req/day/IP. It was in-memory only (worthless on serverless) and blocked test runs; the daily scrape is now the only heavy QUT caller. |

QUT Virtual bootstrap = 2 HTTP requests per cache miss; cache aggressively.

The bulk QUT traffic is the offline scrape (`scripts/scrape-classes.js`), not the app.
That runs at concurrency 6 with a 200 ms stagger per worker, and is resumable — it
reads the existing JSON and only fetches units it has not already stored.

## Testing (Playwright)

One tool covers API, E2E and pure logic — no Vitest/Jest.

```bash
npm test           # everything (24 tests, ~20s when the dev server is idle)
npm run test:api   # app/api/timetable/search contract
npm run test:e2e   # navigation, unit search, auto timetable generator
npm run test:unit  # lib/format-utils overlap + week maths
```

`playwright.config.ts` reuses an already-running dev server on :3000 (`reuseExistingServer`),
so start `npm run dev` first or let it start one.

**Two hard-won rules:**

1. **Do not edit files while the suite is running.** The dev server recompiles on demand,
   and a client chunk that 404s mid-run leaves the page rendered-but-unhydrated. You get
   a red `the app never finished hydrating` that has nothing to do with your change.
   Edit, wait for the compile, then run. An idle run is 24/24 green.

2. **Gate on `main[data-hydrated='true']`** (see `tests/helpers.ts` `gotoApp`). The UI is
   server-rendered and looks interactive before React attaches; a click in that window is
   silently swallowed (the tab takes focus but never changes state). `home-page.tsx` sets
   that attribute from a client effect — do not remove it, and do not replace it with a
   `waitForTimeout`.

The generator is tested through the UI because its Monte Carlo lives in closures inside the
component. Assertions are invariants (every selected unit present, no overlaps, apply fills
the grid), never exact output — it is randomised.

Optional server cache (`lib/kv-cache.ts`) is a no-op without `KV_REST_API_URL` /
`KV_REST_API_TOKEN`; requests go straight to QUT. It logs one info line on first use rather
than throwing per request. Both the timetable route and `/api/clear-cache` share that module.

## Deploying to production

Live at `https://qut-classmate.vercel.app`, project `qut-classmate` under
`danieltsams-projects`. `https://qut.vercel.app` also serves it, but that domain is
still owned by the paused `v0-qut-timetable-planner` project, so it is pinned to a
single deployment instead of following production. Remove the domain from that
project in the dashboard and add it here to make it permanent.

```bash
npx vercel --prod --yes
```

**Two bugs that existed only in production. Both are fixed. Do not undo the fixes.**

1. **Data files must be traced into the serverless bundle.** The API routes read
   `data/*.json` with `fs` at request time. Next only traces static imports, so every
   data route returned ENOENT on Vercel while working perfectly in dev.
   `outputFileTracingIncludes` in `next.config.mjs` is what prevents that. Any new
   route that reads a file with `fs` must be added to it.
2. **The page must not fall back to client-only rendering.** `HomePage` used to call
   `useSearchParams`, which in a static build dereferences to client rendering: the
   deployed HTML contained only "Loading QUT Classmate" and visitors saw a blank
   frame until JS booted. It now reads the tab from `window.location` once on mount
   and the route is `dynamic = "force-dynamic"`. First response is about 45 KB of
   real markup with all four tabs.

Verify a deploy with `curl` against the live URL (`/`, `/api/courses`,
`/api/unit-prereqs`, and a `POST /api/timetable/search`), not with the build log. A
green build says nothing about whether the data shipped.

  -H 'Content-Type: application/json' \
  -d '{"unitCode":"CAB201","teachingPeriodId":"4381474"}'

incrementally, so an interrupted run is not wasted work.

## Voice and copy

Every string a student can read follows the same rules. This is not decoration: the
copy is part of the product, and the audience is someone planning a degree, not
reading marketing.

**Never use:**

1. Sycophancy openers ("Great question!", "Certainly!", "I'd be happy to help").
2. Stock vocabulary as filler: delve, tapestry, testament, journey, realm, pivotal,
   paramount, seamless, holistic, leverage, robust.
3. Hedge-stack openers: "It's important to note that", "Generally speaking",
   "In essence", "At its core".
4. Performative balance. Not every claim needs a "however".
5. Em-dashes in copy a student reads, and tricolon padding. Use a full stop, a
   comma or brackets. A bare `'—'` as a null-value placeholder in a table cell is
   not punctuation and is allowed.
6. Textbook personification and metaphor ("acts like a crisis detector", "paints a
   vivid picture", "serves as a beacon"). Say the actual thing: the number, the
   code, the behaviour.
7. Pseudo-academic grammar labelling ("hazard nouns", "lexical semantic density").
   Quote the actual words instead: "words like fire, burn, and building".

**Tone:** casual Australian English, full sentences, bright Year 12 / first-year uni
level. Ground claims in what the interface actually does or what the data actually
says. Bold only section headers and table captions.

**Enforced by:** `npm run check:copy` (`scripts/check-copy.js`). It strips comments,
then scans `components/` and `app/` for the banned list plus em-dash pileups, and
exits non-zero on a hit. A comment explaining why we avoid a word is not itself a
violation, which is why comments are stripped first.

Two things the checker cannot judge, so they are review-time calls:

- **Which words are load-bearing.** "Leverage" is banned as filler but fine if it is
  genuinely the domain word. The list is a warning to re-read the sentence, not an
  automatic rewrite.
- **Whether a sentence is doing work.** Rule 4 and rule 6 are about substance, not
  vocabulary. If deleting a clause loses nothing, delete it.

## Agent guidelines

1. **Prefer QUT Virtual 4 guest session** for all timetable/unit data — no student credentials.
2. **Always parse `versionNumber` from HTML** — never assume `1`.
3. **Scrape units offline** — don't hit QUT on every autocomplete keystroke.
4. **Keep the diff small** — this app is a focused student tool, not a platform.
5. **Don't commit secrets** — `.env*` is gitignored; use `.env.example`.
6. **Teaching period IDs rot yearly** — document how to refresh them from QUT Virtual HTML.
